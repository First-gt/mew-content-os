# เอกสารรีวิวปัญหา UI/UX และแนวทางแก้ไขเฉพาะจุด (Founder UI/UX Review & Fix Plan)
**ระบบ**: MEW Content OS  
**ผู้ตรวจ**: Founder & Technical QA  
**วันที่**: 1 พฤศจิกายน 2026  
**สถานะ**: รอยืนยันคำสั่ง "พร้อม" เพื่อให้ AI เริ่มการแก้ไข  

---

## 1. ปัญหาสำคัญที่พบจากการใช้งานจริง (Critical Issues Found)

### 🔴 ปัญหาที่ 1: การเอาทุกหน้ามากองรวมกันในหน้าเดียว (Page Stacking & Infinite Scroll Bloat)
- **อาการที่เกิดขึ้น**: เมื่อเปิดหน้าเว็บและเลื่อน Scroll ลงมาเรื่อย ๆ จะพบว่าหน้า **Research**, **Library**, **Remix**, และ **Content Board** ถูกเอาโค้ด HTML มาต่อกันยาวเป็นกิโลในหน้าเดียว
- **ผลกระทบ**: ผู้ใช้เลื่อนดูหน้าแรกแล้วดันเลื่อนทะลุไปเจอหน้า Library แล้วทะลุต่อไปเจอหน้า Remix ทำให้ผู้ใช้งานสับสนอย่างรุนแรง ไม่เข้าใจลำดับการทำงาน และหน้าเว็บดูเละเทะ ไม่มีความเป็นมืออาชีพ
- **สาเหตุเชิงลึก**:
  1. ไฟล์ `index.html` ที่อยู่ที่โฟลเดอร์ราก (`D:\project\index.html`) เป็นไฟล์เก่าขนาด 1 MB ที่สร้างไว้ตั้งแต่วันที่ 29 ต.ค. ซึ่งยัดทุกหน้าเรียงกันแบบ Hardcode
  2. ในสคริปต์ประกอบหน้าเว็บ (`_assemble_index_html`) มีการนำเนื้อหา HTML ของทุกโมดูลมาแปะต่อกันในแท็ก `<main>` โดยไม่มีการแยก View Container ให้เป็น Single-Page App (SPA) ที่แท้จริง
  3. กฎ CSS เดิมไม่ได้บังคับให้ซ่อนหน้าอื่นอย่างเด็ดขาด (`display: none !important`) ทำให้เมื่อเปิดบางเบราว์เซอร์หรือขนาดหน้าจอต่างกัน ทุกหน้าจึงโผล่ออกมาพร้อมกันทั้งหมด

---

### 🔴 ปัญหาที่ 2: ระบบ Tab และ Router ไม่ยอมซ่อนหน้าอื่น (Broken View Isolation)
- **อาการที่เกิดขึ้น**: การคลิกสลับแท็บเมนูด้านบน (Overview / Research / Library / Remix / Board) ไม่ได้เปลี่ยนหน้าแบบโดดเดี่ยว แต่ทำแค่ไฮไลต์ปุ่ม โดยที่เนื้อหาของหน้าอื่นยังคงกองอยู่ด้านล่าง
- **สิ่งที่ต้องเป็น**:
  - เมื่อผู้ใช้อยู่หน้า **Overview**: ต้องเห็น**เฉพาะ**หน้า Overview เท่านั้น หน้าอื่นต้องหายไปจาก DOM/Viewport 100%
  - เมื่อผู้ใช้อยู่หน้า **Research**: ต้องเห็น**เฉพาะ**หน้า Research เท่านั้น
  - เมื่อผู้ใช้อยู่หน้า **Library**: ต้องเห็น**เฉพาะ**หน้า Library สองคลังเท่านั้น
  - เมื่อผู้ใช้อยู่หน้า **Remix**: ต้องเห็น**เฉพาะ**ห้องทดลอง Remix เท่านั้น
  - ผู้ใช้ต้องไม่สามารถเลื่อน Scroll จากหน้าหนึ่งทะลุไปโผล่อีกหน้าหนึ่งได้โดยเด็ดขาด

---

### 🔴 ปัญหาที่ 3: ความรกของดีไซน์และศัพท์เทคนิค (Visual Bloat & Spec Jargon Overload)
- **อาการที่เกิดขึ้น**: มีป้ายและโค้ดเทคนิค เช่น `S00`, `S01`, `S02`, `S04`, `S06 · S07`, `C(N)+P(N)`, `Formula C ≥ 1`, `DUAL-LENS DECONSTRUCTION WORKSPACE` โผล่มาเต็มหน้าเว็บ
- **สิ่งที่ต้องเป็น**:
  - ซ่อนรหัสวิศวกรรมภายในทั้งหมด ผู้ใช้จริงต้องการแค่คำที่เข้าใจง่าย เช่น **"วิจัยคลิป"**, **"คลังไอเดีย"**, **"ห้องรีมิกซ์"**, **"กระดานติดตามงาน"**
  - ดีไซน์ต้องสะอาด สบายตา มี White Space และมีปุ่มหลัก (Primary CTA) ที่เด่นชัดเพียงปุ่มเดียวในแต่ละหน้า

## 2. แผนการแก้ไขเฉพาะจุดสำหรับส่งให้ AI (Targeted AI Fix Instructions)

เมื่อได้รับคำสั่ง "พร้อม" AI จะทำการแก้ไขตาม 4 ขั้นตอนนี้ทันที:

### ขั้นตอนที่ 1: ยกเครื่องระบบ Tab & View Container ให้เป็น Isolated Single View
- **ไฟล์เป้าหมาย**: `src/index.html`, `src/styles/main.css`, `src/modules/router.js`
- **แนวทางแก้ไข**:
  1. กำหนดให้คอนเทนเนอร์ของแต่ละหน้า (`#view-overview`, `#view-research`, `#view-library`, `#view-remix`, `#view-board`) มีคุณสมบัติ:
     ```css
     .view-section {
       display: none !important;
       width: 100%;
       min-height: calc(100vh - 70px);
     }
     .view-section.active {
       display: block !important;
     }
     ```
  2. อัปเดต `router.js` และสคริปต์สลับหน้า: เมื่อมีการกดปุ่มสลับแท็บด้านบน จะทำการถอดคลาส `active` ออกจากทุกหน้า แล้วใส่ `active` ให้เฉพาะหน้าที่ถูกเลือก พร้อม Reset Scroll กลับไปด้านบนสุดเสมอ

### ขั้นตอนที่ 2: อัปเดตไฟล์หลัก `D:\project\index.html` ให้ตรงกับเวอร์ชันล่าสุด
- แทนที่ไฟล์เก่าขนาด 1 MB ที่รากโปรเจกต์ด้วยโครงสร้าง SPA แบบใหม่ที่แยกหน้าสมบูรณ์ เพื่อไม่ให้เกิดการเปิดไฟล์ผิดเวอร์ชัน

### ขั้นตอนที่ 3: จัดระเบียบเนื้อหาภายในแต่ละหน้า ไม่ให้ซ้อนทับกัน
- ในหน้า **Research**: รวม S01 (กล่องวาง URL/Inbox) และ S02 (รายละเอียดคลิป) ให้สลับกันอย่างลื่นไหลเมื่อกดเลือกคลิป ไม่นำมากองต่อกัน
- ในหน้า **Library**: แสดงแท็บคลัง 2 คลัง (Content / Packaging) แบบกะทัดรัด
- ในหน้า **Remix**: จัดวาง 3 คอลัมน์ (วัตถุดิบ ➔ ทิศทาง ➔ ไอเดียใหม่) ให้อยู่ในหน้าจอเดียวโดยไม่ต้องเลื่อนยาว

### ขั้นตอนที่ 4: ตรวจสอบความถูกต้องด้วยชุดทดสอบอัตโนมัติ
- รัน `npx playwright test` และ Node unit tests ทั้งหมด เพื่อยืนยันว่าการแยกหน้าไม่กระทบฟังก์ชันและเส้นทางการทำงานเดิม
